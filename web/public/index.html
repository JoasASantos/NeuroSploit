Auth & Keys
Used so agents test as a logged-in user. Kept only for this session, sent to the CLI as an ephemeral creds file.
Two or more roles enable IDOR/BOLA/BFLA cross-role testing.
Keys are kept in this server process's memory only — never written to disk. Cleared on restart.
The signed grant for this engagement: who authorized it, which hosts, which environment, until when. It is verified by the harness (NEUROSPLOIT_CAPABILITY_KEY) and acts as a ceiling — the settings below can narrow the scope, never widen it. Mint one with neurosploit capability issue.
Without this the engagement is authorized against the target and nothing else — discovering a host is not permission to test it.
Scales every risk score — the same action is a different act on a lab bench and on a live substation.
OT blocks writes, disruptive actions, fuzzing and exploit payloads over industrial protocols, and caps the rate at ~1 req/s.
An explicit file on disk — see neurosploit-rs/creds.example.yaml for the schema (jwt/header/cookie/login/roles/ssh/windows/cloud).
